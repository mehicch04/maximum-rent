MAXIMUM RENT A CAR — popravka konzolnih React grešaka (Best Practices 96 -> 100)
================================================================================

STA JE BILO
-----------
PageSpeed je prijavljivao React greske #418 / #423 / #425 u konzoli. Sve su to
"hydration mismatch" -- server iscrta jedan HTML, a browser pri hidraciji
drugaciji, pa React prijavi gresku (i to obara "Best Practices" na 96).

UZROK  [components/reservation/ReservationSearchForm.tsx]
-----
Search forma u herou je racunala default datume iz new Date() VEC pri renderu
(useState(dateOffset(1)) itd.). Server je u UTC vremenu, a posjetilac/testni
browser u drugoj vremenskoj zoni, pa se izracunati datum (value/min inputa)
razlikovao server vs browser -> mismatch.

(Provjereno: OpenStatus je vec ispravno gejtan; InquiryModal vraca null dok se
auto ne odabere pa nije u SSR-u; nema drugih render-time uzroka na naslovnoj.)

RJESENJE
--------
Default datumi (preuzimanje, vracanje) i "min" datum se sada racunaju NAKON
mounta (useEffect), jer default treba da bude KORISNIKOV lokalni "sutra", sto
samo browser zna. Pocetno stanje je prazno -> isto na serveru i klijentu ->
nema mismatcha. Datumi se popune istog trena po ucitavanju.

Ponasanje je isto kao prije za korisnika (polja se popune sama), samo bez
konzolnih gresaka.

FAJL
----
  components/reservation/ReservationSearchForm.tsx

KORACI
------
1. Raspakuj preko root-a.
2. npm run dev -> naslovna: search forma se popuni datumima; u DevTools Console
   nema vise React #418/#423/#425.
3. git add . && git commit -m "fix: hydration mismatch u search formi (default datumi -> useEffect)" && git push
4. Ponovo PageSpeed -> Best Practices bi trebao biti 100 (mobitel i desktop).

Napomena: alat za prikaz slika mi je u ovoj sesiji u kvaru pa nisam vizuelno
provjerio, ali TypeScript je cist i logika je standardni fix za ovaj tip greske.

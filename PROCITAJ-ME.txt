MAXIMUM RENT A CAR — jos brze ucitavanje vozila (keširanje)
===========================================================

STA JE DODANO (na prethodni fix sa prioritetom slika)
-----------------------------------------------------
Lista auta i lokacije se sada KESIRAJU. Ranije se baza pozivala pri SVAKOJ
posjeti stranici /vozila. Sada se odgovor cuva u Next Data Cache-u, pa stranica
krece gotovo trenutno (nema DB poziva na kriticnom putu = brzi TTFB).

Svjezina podataka (sigurno):
  - Kes se osvjezava svakih 5 minuta, ILI
  - ODMAH kad u adminu dodas / uredis / obrises auto (revalidateTag("fleet")).
Znaci nikad ne vidi zastarjelu listu nakon tvoje izmjene.

Vazno: pretraga PO DATUMU (dostupnost) NIJE kesirana — ostaje uzivo, da se
nikad ne prikaze vec rezervisan auto kao slobodan.

FAJLOVI
-------
  lib/fleet-data.ts                 (NOVO — kesirani upiti: getBrowseCars, getActiveLocations)
  app/[locale]/vozila/page.tsx      (koristi kesirane upite + prioritet slika + preconnect)
  app/admin/vozila/actions.ts       (revalidateTag("fleet") pri izmjeni flote)
  components/fleet/FleetGrid.tsx    ]
  components/fleet/CarCard.tsx      ]  (prioritet prvih slika — iz proslog fixa,
  components/fleet/CarGallery.tsx   ]   ukljuceno da zip radi samostalno)
  components/ui/WhatsAppIcon.tsx     (zavisnost CarCard-a)

STA SVE SADA UBRZAVA /vozila
----------------------------
1. Prve 3 slike auta se ucitavaju odmah (eager + prioritet).
2. Preconnect na Supabase (brza veza za slike).
3. Lista auta iz kesa (bez DB poziva svaki put) -> brzi TTFB.

KORACI
------
1. Raspakuj preko root-a.
2. npm run dev -> /vozila se ucita brze; dodaj auto u adminu pa provjeri da se
   odmah pojavi u listi (kes se busta).
3. git add . && git commit -m "perf(fleet): kesiraj listu auta + on-demand revalidate" && git push

Schema NIJE mijenjana -> nema prisma generate / db push.
